This is my mid-semester project. I built a small Flutter task-manager where I sign in, create agendas for specific days and times, attach a photo and a map-pinned location, optionally set a reminder, and the app pops up a notification when the start time hits.

I designed it to satisfy the five required capabilities:

| # | Requirement | How I covered it |
|---|---|---|
| 1 | **CRUD with a relational database** | I store data locally in sqflite with two related tables — `tasks` and `categories` — connected by a foreign key (`ON DELETE RESTRICT`). Both tables have full create/read/update/delete UI, and I run a real JOIN query when I render the daily list. |
| 2 | **Firebase Authentication** | Email/password sign-in, register, forgot-password, sign-out, and delete-account. Errors are mapped to friendly messages instead of raw Firebase codes. |
| 3 | **Storing data in Firebase** | Every task and category I create also writes to Cloud Firestore under `users/{my-uid}/`. I'm on the free Spark plan, so I don't use Firebase Storage or Cloud Messaging — task photos stay on the device. |
| 4 | **Notifications** | I picked a hybrid approach: a system tray notification (via `flutter_local_notifications`) AND an in-app pop-up overlay that slides down from the top. That way I see reminders whether the app is open or closed. |
| 5 | **Smartphone resource** | Camera via `image_picker`, and GPS via `geolocator`. For the location, I can also pick a place by name on an OpenStreetMap with Nominatim search — so a task can store something like "Tunjungan Plaza" instead of just lat/lng. |

## How to run it

### 1. Hook up your Firebase project

I used the free Spark plan. In the [Firebase console](https://console.firebase.google.com), create a project and turn on:

- **Authentication → Sign-in method → Email/Password**
- **Firestore Database** (Native mode, any region)

You don't need Storage or Cloud Messaging — I worked around both.

### 2. Generate the platform configs

```bash
brew install firebase-cli                  # or: npm install -g firebase-tools
dart pub global activate flutterfire_cli
firebase login

cd /path/to/ets1
flutterfire configure                       # pick your Firebase project, target android + ios
```

That writes `lib/firebase_options.dart`, `android/app/google-services.json`, and `ios/Runner/GoogleService-Info.plist`.

### 3. Deploy the Firestore rules

Paste this into Firestore → **Rules** in the console and **Publish**:

```js
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
      match /tasks/{taskId} {
        allow read, write: if request.auth != null && request.auth.uid == uid;
      }
      match /categories/{catId} {
        allow read, write: if request.auth != null && request.auth.uid == uid;
      }
    }
  }
}
```

This locks each user to their own subtree.

### 4. Install and launch

```bash
flutter pub get
cd ios && pod install && cd ..
flutter run --profile
```

I worked around it by always running in **profile mode**, which uses AOT-compiled native code (no JIT, so iOS doesn't kill it). The wrapper just runs:

```bash
flutter run --profile
```

### Data model

**sqflite** (local, schema v2):

| Table | Fields (abridged) |
|---|---|
| `categories` | `id`, `remoteId`, `userId`, `name`, `colorHex`, `createdAt`, `updatedAt` |
| `tasks` | `id`, `remoteId`, `userId`, **`categoryId`** (FK → `categories.id` ON DELETE RESTRICT), `title`, `description`, `date`, `startTime`, `endTime`, `isCompleted`, `localImagePath`, `latitude`, `longitude`, `locationName`, `reminderEnabled`, `syncStatus`, timestamps |

**Firestore** (cloud, sub-collections under each user):

```
users/
  {uid}/                              ← profile doc (email, createdAt, lastSeenAt)
    categories/{auto-id}              ← { name, colorHex, timestamps }
    tasks/{auto-id}                   ← { categoryRemoteId, title, description, date,
                                          startTime, endTime, isCompleted,
                                          location: { latitude, longitude, name },
                                          reminderEnabled, timestamps }
```

I kept Firestore as nested sub-collections because it makes the security rules trivial (a user can only touch their own subtree) and avoids needing composite indexes.

### How writes flow

When I save a task, the controller does:

```
sqflite.insertTask(syncStatus='pending')          ← always succeeds, even offline
  ↓
firestore.upsertTask                              ← may fail; Firestore SDK queues offline
  ↓
sqflite.update(remoteId, syncStatus='synced')
  ↓
notification.scheduleTaskReminder                 ← if Remind me is on
```
